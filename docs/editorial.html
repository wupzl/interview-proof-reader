关于这份案卷

原稿与编辑方式

本书改编自用户提供的《面试官的审判》Markdown。原稿保存在仓库 source/interviewdescription.md，校验值见 CONTENT_REVIEW.json；编辑后的七章位于 chapters/，可独立维护。人物、情节与七章结构保留，第八章只保留预告，当前状态为连载。

本次编辑清理了复制按钮、预填自评分数、重复预告标题和导出残片；将面向原对话用户的表述改为公开阅读措辞；把错误导出的公式改为可复制、可被读屏读取的文本，重新整理指标表格与反问清单。七组训练为本项目补充的学习材料，参考答案是思路示例，不是对任何人的真实经历描述。

技术项目素材

训练题参考了用户补充的技术简历，聚焦两类项目：Coding Agent Runtime 与文档检索问答平台。素材包括 Provider 流式事件适配、JSONL Memory、上下文压缩、MCP 工具延迟加载、Heading Path 分块、pgvector、metadata-aware rerank 和检索评测。项目背景已经概括处理；原始简历、姓名、联系方式、学校及雇主信息未收录。

简历中的结果不自动等同于已独立核实的事实。练习会要求填写样本、实验环境、统计口径、个人职责及验证材料。BM25/RRF 是书中的通用技术讨论，不代表参考项目已经实现。任何示例都需要按自己的真实经历调整。

技术核对与阅读边界

  • 普通队列下，ThreadPoolExecutor 达到核心线程数后优先入队，无法入队时再尝试扩容。示例中的实际线程数也受提交与任务完成时序影响。参见 Java 官方 API 文档。
  • Redis 锁需要区分所有权校验、锁有效期和故障假设。解锁应检查令牌归属，简单设置过期时间不能覆盖所有并发问题。参见 Redis 官方分布式锁说明。
  • RRF 依据不同结果列表中的排名融合候选，不等于直接相加原始相似度分数。参见 Elastic 官方 RRF 文档。
  • Little 定律 L = λ × W 描述稳定系统的长期平均量，单位和系统边界必须一致；QPS、并发请求和连接数量不能随意互换。
  • Hit@K 表示是否命中至少一个相关项；Recall@K 需要全部已标注相关项作为分母。单正例情况下部分指标可能相等，多正例下不能混用。MRR 关注首个相关结果的位置。
  • 0.48→0.64 是增加 16 个百分点，相对提升约 33.3%。算术正确不等于实验结论可靠，仍需报告样本、对照与局限。
  • 书中压测数字、候选人评语与模型化表达均用于教学。涉及 GC、SDK、模型和框架的实现细节，需要对照实际版本；本次核对聚焦上述关键表述，不代表对全部技术内容完成独立复现。

训练如何工作

所有填写、自查、计时与简单计算都在浏览器完成。复盘展示考察点、参考思路和你勾选的自查项目，不自动判断答案正确性，也不代表招聘方评分。点击“复制 AI 点评提示词”只复制文字，由你决定是否粘贴到外部工具。

记录保存在当前浏览器，不跨设备同步；清除网站数据可能使记录丢失。可将训练导出为 Markdown，并下载 JSON 备份。使用共享设备时，请自行管理本地记录和导出文件。
